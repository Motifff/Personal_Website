# 项目文档编写指南

## 核心结构

借鉴 Jason Spielman 的 NotebookLM 文档风格，每个项目文档应遵循以下叙述逻辑：

```
问题/背景 → 心智模型 → 方案/核心设计 → 细节/场景 → 反思/洞察
```

---

## 文档层级模板

### 1. 元信息

```json
{
    "title": "项目名称",
    "subtitle": "一句话描述核心价值",
    "type": "分类标签",
    "location": "地点",
    "date": "时间"
}
```

**写作要点：**
- title：简洁，不用修饰词
- subtitle：用户价值导向，而非功能描述
  - ❌ "一个基于LLM的聊天系统"
  - ✅ "颠覆传统流量模型，构建以用户价值为核心的增值飞轮"

---

### 2. 开篇段落

**目标：** 让读者在 30 秒内理解项目核心价值

**结构：**
```
[项目定位] + [解决什么问题] + [如何解决] + [核心成果]
```

**示例 (grad_design_2025):**
```
本项目是UCL表演与交互设计硕士论文。研究探索一种创新UX范式：
基于LLM的多利益相关者圆桌讨论模拟系统。

核心痛点：传统设计研究中，整合多方意见面临信息过载、认知负担、数据碎片化。

解决方案：设计师圆桌系统，让AI Agent模拟不同背景、性格的利益方进行辩论协作。
```

---

### 3. 问题/痛点

**何时使用：**
- 产品类项目：用户痛点
- 研究类项目：学术gap或实际问题

**写法：**
```
Core Pain Points: [痛点标题]
- [痛点1]：具体表现
- [痛点2]：具体表现
```

**示例 (qwen_chat_mock):**
```
传统DAU流量模型的局限：
- 用户被动等待生成结果
- 上下文断裂，意图丢失
- 手机沦为低效输入工具
```

---

### 4. 方案/核心设计

**结构：**
```
Solution: [方案名称]

- [模块1]：[功能 + 设计意图]
- [模块2]：[功能 + 设计意图]
- [交互/体验]：[如何使用]
```

**示例:**
```
Solution: 智能连续输入系统

- Instant Feedback：半透明非侵入式显示，实时预览
- Silent Efficient Input：支持文字/语音/应用导航等多模态
- Controllable Behavior：用户可随时打断流式输出
```

---

### 5. 心智模型（推荐新增）

**作用：** 帮助读者理解用户如何使用你的设计

**格式：**
```
Mental Model: [流程箭头]

用户 → [第一步] → [第二步] → [最终状态]
```

**示例:**
```
Mental Model:

Inputs → Chat → Outputs
(上传源材料) → (AI问答/合成) → (笔记/音频摘要)

传统ChatGPT: 单轮问答
NotebookLM: 源材料驱动的持续创作
```

---

### 6. 设计思考/洞察

**目标：** 展示设计决策背后的思考

**格式：**
```
Core Design Thinking:

- [从X到Y]：[原有范式] → [你的新范式]
- [创造XX体验]：[如何实现]
- [XX创新]：[核心技术/设计突破]
```

**示例:**
```
Core Design Thinking:

- 从被动等待到主动控制：受Cursor Tab启发，将内容填充交互升维
- 创建Flow体验：用在线强化学习捕捉用户意图，自动桥接任务间隙
- 智能连续性：不只预测下一个词，而是连接概念跳跃
```

---

### 7. 细节/场景

**适用于：** 有多个功能模块或使用场景的项目

**可用组件：**
| 组件 | 用途 |
|------|------|
| `heading` | 分节标题 |
| `imageBed` | 图片展示（多图轮播） |
| `paragraph` | 文字段落（支持Markdown） |
| `quote` | 引用/强调 |
| `link` | 外部链接 |

---

### 8. 反思/关键收获（可选）

**用于：** 总结设计过程中的学习

```
Key Takeaways:

1. [产品层面的洞察]
2. [技术层面的洞察]
3. [用户层面的洞察]
```

## 各项目推荐结构

### UX/产品类项目 (qwen_chat_mock, myo_clear_app)

```
1. 开篇：用户价值导向
2. 痛点：用户当前困境
3. 方案：核心功能 + 设计意图
4. 设计思考：范式转变
5. 场景：不同使用场景
```

### HCI/交互类项目 (detective_retoric, enhanced_spine)

```
1. 开篇：交互体验定位
2. 问题：现有交互的局限
3. 方案：交互机制设计
4. 心智模型：用户操作流程
5. 视频/GIF：交互演示
```

### 研究类项目 (grad_design_2025)

```
1. 开篇：研究定位 + 学术背景
2. 问题：学术gap或实际问题
3. 方案：系统架构
4. 设计思考：方法论创新
5. 技术细节：核心技术实现
```

### 空间/装置类项目 (tea_space, material_movement)

```
1. 开篇：空间定位
2. 设计意图：想要创造什么体验
3. 技术实现：装置如何运作
4. 空间照片：实景展示
```

## 写作风格建议

### 1. 用动词而非形容词

❌ "这是一个智能的系统"
✅ "系统实时捕捉用户意图"

### 2. 用对比突出创新

️ "支持多模态输入"
✅ "从单一文字输入到文字/语音/导航的静默多模态"

### 3. 用场景而非功能列表

❌ "功能：即时反馈、静默输入、可控行为"
✅ "用户开始输入 → 系统半透明预览 → 用户打断 → 调整方向"

### 4. 每个段落有明确主题

开头第一句即陈述本段核心观点，不铺垫。
